# Система учёта заказов — Производство ковров

Веб-приложение для учёта заказов на чистку, ремонт и обработку ковров (и любого другого производства с приёмкой-выдачей: прачечная, химчистка, реставрация): клиенты, заказы, позиции, услуги, исполнители, логистика, производство, оплата, гарантия.

Документ состоит из двух частей:

- **Часть 1 — Инструкция оператору.** Для человека, который ежедневно работает с приложением. Никаких технических знаний не нужно.
- **Часть 2 — Инструкция администратору.** Для того, кто настраивает справочники (типы изделий, каталог SKU, сотрудники, роли, районы), читает обращения и аналитику.

> Установка и развёртывание сервера, автообновление из git, бэкапы — отдельный документ `SERVER.md` для сисадмина.
>
> Тренажёр для обучения новых операторов (отдельная база, безопасная песочница с интерактивным туром) — раздел ниже «ЧАСТЬ 3. ТРЕНАЖЁР».

> **Важно про модель данных (с релиза V10).** Услуги в системе живут в виде плоского **каталога SKU** — каждая запись описывает конкретную учётную единицу (например, «Стирка ковёр шерсть 5–10 кг»). У SKU есть цена, тип расчёта, атрибуты (тип вещи, материал, диапазон веса/площади/периметра…) и опциональный флаг «авто-добавлять в каждый заказ». Старая двумерная таблица «тип позиции × услуга» больше не используется. Подробнее — в §2.2.

# ЧАСТЬ 1. ИНСТРУКЦИЯ ОПЕРАТОРУ

> Эта часть — для того, кто будет каждый день вести заказы. Никакого айти не нужно. Все действия делаются мышкой в браузере.

## 1.1. Вход

1. Открой браузер (Chrome, Edge, Safari — любой современный).
2. Введи адрес сайта (его даст администратор).
3. На экране входа набери логин и пароль.
4. После входа сразу попадаешь на главную страницу.

Если случайно закрыл вкладку — ничего страшного, просто снова войди. Никакие данные не теряются.

## 1.2. Меню (слева)

Все разделы — в боковой панели слева:

| Раздел        | Зачем                                                                  |
|---------------|------------------------------------------------------------------------|
| **Главная**   | Виджеты с цифрами на сегодня и блок «Проблемные заказы».              |
| **Заказы**    | Вся работа с заказами — твой главный экран.                            |
| **Позиции**   | Поиск конкретного ковра по разным признакам.                           |
| **Логистика** | Календарь на неделю: что забираем и доставляем по дням.               |
| **Производство** | Доска с заказами, позициями или услугами в работе.                  |
| **Аналитика** | Графики и цифры по выручке, заказам, статусам.                        |
| **Клиенты**   | База клиентов и их история.                                           |
| **Связь с разработчиком** *(плавающая кнопка справа внизу)* | Если что-то непонятно или сломалось — отсюда отправляешь обращение разработчику. |

Если включён режим супервизора (это для администратора, обычно тебе не нужно), вокруг экрана появится тонкая оранжевая рамка — значит видны дополнительные пункты меню (Справочники, Сотрудники, Доходность, Обращения, логи).

> 👁 **Режим просмотра (для моноблока).** На странице входа есть чекбокс «Войти в режиме просмотра». В этом режиме интерфейс работает только на чтение: кнопки создания заказов, смены статусов и редактирования скрыты. Используется на общем мониторе в офисе, чтобы любой сотрудник мог посмотреть состояние дел, но ничего случайно не сломал.

> 📱 **Личный кабинет работника.** Для мастеров чистки, прачек и водителей есть отдельный вход: с экрана `/login` ссылка «Вход для работника →». Работник тыкает свою плитку, вводит 4-значный PIN и видит только свои услуги на сегодня. Подробнее — в разделе «1.15. Личный кабинет работника».

## 1.3. Жизненный цикл заказа

Понимать его важно — вся работа сводится к переключению заказа между статусами.

```
Лид → Создан → К забору → В работе → Частично готов → Готов → Доставлен → Завершён
                                                            │
                                                            └─ может появиться Гарантийный возврат
```

Что значит каждый статус:

- **Лид** — клиент только позвонил, ничего ещё не подтвердили.
- **Создан** — заказ оформлен, ковры пока у клиента.
- **К забору** — назначены дата и время, машина едет.
- **В работе** — мастера начали работать. *Ставится автоматически.*
- **Частично готов** — часть позиций готова, часть в работе. *Ставится автоматически.*
- **Готов** — всё сделано, ждём оплату и доставку. *Ставится автоматически.*
- **Доставлен** — клиент получил ковры.
- **Завершён** — заказ полностью закрыт (после доставки и оплаты).
- **Отменён** — заказ отменили.
- **Гарантийный возврат** — отдельный новый заказ, если клиент пожаловался уже после доставки.

**Вручную ты переключаешь только:**
- Лид → Создан
- Создан → К забору
- Готов → Доставлен (или сразу «Принять оплату» — кнопка делает обе операции)
- Любой → Отменён (с обязательным указанием причины)

> Над статусом есть кнопка **«?»** — она открывает памятку прямо в приложении. Если забыл что-то — открой её.

## 1.4. Сценарий: новый заказ

### Шаг 1. Создать заказ

1. В меню → **Заказы** → справа сверху **+ Новый заказ**.

### Шаг 2. Указать клиента

**Если клиент уже есть** — «Выбрать существующего», начни печатать имя/телефон/название.
- Если у клиента уже сохранён адрес — он сразу подставится в поля забора и доставки (вместе с районом и координатами). Если адрес другой — поставь галку *«Указать другие адреса для заказа»* и введи.

**Если клиент новый** — «Создать нового»:
- Тип: *Физ. лицо* / *Юр. лицо*.
- Заполни нужные поля. Телефон вводится в формате `+7 (XXX) XXX-XX-XX` — система сама подставит маску и проверит длину.
- При вводе телефона система ищет клиентов с таким же номером и предлагает выбрать существующего, чтобы случайно не создать дубль.
- В поле **Адрес** — выпадающий список реальных адресов с автоопределением района и координат. Выбери клавишами или мышкой.
- ИНН (для юрлица, опционально) — система проверяет контрольную сумму.

### Шаг 3. Указать адреса забора и доставки

По умолчанию используется адрес клиента. Если нужны другие — поставь галку *«Указать другие адреса для заказа»* и заполни.

Если адрес уже подтверждён (взят из карточки клиента или выбран из подсказок DaData) — никаких предупреждений нет. Если ввёл руками без подсказок, появится бейдж *«адрес не подтверждён»* — координат не будет, на карте точка не отобразится.

### Шаг 4. Создать заказ → откроется страница заказа

На этом этапе у заказа статус **Лид**.

### Шаг 5. Добавить позиции (ковры/изделия)

Каждая позиция — это один ковёр или одно изделие.

1. На странице заказа — раздел **«Позиции заказа»** → **+ Добавить позицию**.
2. Выбери **тип** (Ковёр, Палас, Шторы и т.п.).
3. **Описание** — то, что отличает это изделие («зелёный 2×3 из спальни», «персидский»).
4. **Добавить**.

> **Совет.** Если у клиента несколько одинаковых изделий — после первого добавления нажми кнопку **Дубль** в строке этой позиции.

> **Авто-добавленные позиции (доставка/приём и т.п.).** Если в каталоге SKU есть учётные единицы с флагом «авто-добавлять» (§2.2), при создании заказа они автоматически появятся как отдельные позиции с уже привязанной услугой. Например, SKU «Доставка стандартная» с атрибутом «тип вещи = Доставка» — в каждом новом заказе сразу появится позиция «Доставка» + услуга «Доставка стандартная» на 500 ₽. Если в каталоге задан **порог бесплатной доставки** (например, бесплатно от 3 000 ₽), цена пересчитывается автоматически по мере наполнения заказа.

### Шаг 6. Заполнить размеры

Размеры нужны для услуг, цена которых считается по площади / весу / периметру / длине / ширине / погонным метрам. Без размеров такая услуга добавится, но её **нельзя будет перевести в работу** — мастера сразу увидят жёлтую плашку «Не заполнены размеры».

1. В строке позиции кликни на колонку **Размеры**.
2. Заполни нужные поля:
   - длина и ширина — для услуг «по площади»;
   - периметр — отдельно для овальных/круглых изделий, у которых формула 2·(длина+ширина) не работает;
   - вес — для «по весу»;
   - погонные метры — для «по пог. метру».
3. Зелёная галочка — сохранить.

### Шаг 7. Добавить услуги к позиции

1. Разверни позицию (▼).
2. В подразделе **«Услуги»** → кнопка **«+ Добавить услугу»**.
3. Открывается модалка **«Выбор услуги (SKU)»**:
   - Сверху — фильтр по группе («Стирка», «Чистка», «Реставрация», «Доставка», «Приём»).
   - Поле поиска по названию.
   - Чекбокс **«Только подходящие»** *(включён по умолчанию)* — оставляет только те SKU, чьи атрибуты-диапазоны совпадают с параметрами твоей позиции (тип вещи, вес, площадь и т.п.). Подходящие подсвечены зелёной полосой и галочкой `✓` в первой колонке.
   - Если ничего не подобралось — сними галочку «Только подходящие», увидишь весь каталог. Это нужно, если ты добавляешь нестандартную услугу.
4. На нужной строке → **+ Выбрать**. Цена считается автоматически: фиксированная сумма или цена × (вес/площадь/…).

> **Дубли запрещены.** Одну и ту же услугу нельзя добавить к одной позиции дважды. Если хочешь повторить — сначала отмени уже добавленную, тогда можно добавить заново.

> **Размеры можно заполнить позже.** Услугу можно добавить сразу, даже если размеры ещё не введены. Заполнить нужно будет до перевода услуги в «В работе» — иначе появится модалка «Заполните размеры».

### Шаг 8. Дефекты, фото

- **Дефекты** — кликни на колонку «Описание / Дефекты» позиции, заполни второе поле. Защитит от споров с клиентом.
- **Фото** — разверни позицию, в блоке «Фото» нажми «Добавить фото». Несколько фото — клик по фото → открывается на полный экран.

### Шаг 9. Скидки/наценки

В блоке **«Расчёт стоимости»** внизу страницы заказа:
- **+ Добавить модификатор...** — выпадающий список (например, «Скидка пенсионерам -10%»).
- Если у клиента модификатор должен применяться всегда — после добавления нажми **«Сохранить модификаторы в клиента»**: в его новых заказах модификатор подставится автоматически.

### Шаг 10. Перевести в «Создан»

Сверху заказа — кнопка **«Сменить статус...»** → **Создан**.

### Шаг 11. Назначить дату забора

В блоке **«Логистика и детали»** → **«Редактировать»**:
- **Дата забора** + **Время забора** (есть три временных слота).
- **Сохранить**.

Затем сверху заказа смени статус на **К забору**.

> Дату удобно ставить через раздел **Логистика** — там можно перетаскивать заказы по дням мышкой.

## 1.5. Сценарий: ковры приехали в производство

1. Зайди в заказ (через «Заказы» или «Производство»).
2. Разверни позицию.
3. Найди услугу.
4. **Назначь исполнителя** — кнопка «Исполнители». Откроется окно со списком сотрудников.
   - В шапке окна написано, какая роль подходит для этого типа позиции (например, «Видны исполнители: с ролью "Рабочий" или без роли»). Это значит, что система автоматически отфильтровала тех, кто умеет работать с этим типом изделия.
   - Возле каждого имени — бейдж его роли или «универсал» (сотрудник без роли). Универсалы видны в любом окне исполнителей — это сделано специально, чтобы добавление новых типов позиций не парализовало работу.
5. **Поставь статус услуги** через выпадающий список:
   - **Создана** — пока никто не делал.
   - **В работе** — мастер взял.
   - **Готова** — мастер закончил.
   - **Отменена** — отказались делать (нужна причина, минимум 10 символов).

Когда хотя бы одна услуга встала в **«В работе»**, статус заказа автоматически перейдёт в **«В работе»**. Когда часть позиций готова — **«Частично готов»**. Когда все — **«Готов»**.

## 1.6. Сценарий: заказ готов, клиент платит

Когда заказ перешёл в **«Готов»**:

**Вариант 1 (быстрый):** клиент пришёл и платит на месте.
- Появится зелёная кнопка **«Принять оплату»**.
- Окно: дата доставки, временной слот, тип оплаты.
- Жмём — заказ переходит в **«Доставлен»** + фиксируется оплата за один шаг.

**Вариант 2 (раздельный):**
1. Назначь дату доставки в блоке «Логистика и детали».
2. Смени статус на **«Доставлен»**.
3. Появится кнопка **«Оплатить»** — выбери тип оплаты.

После доставки и оплаты заказ можно перевести в **«Завершён»**.

## 1.7. Сценарий: гарантийный возврат

Клиент позвонил и пожаловался уже после доставки:

1. Открой заказ. Он должен быть в статусе **«Доставлен»** или **«Завершён»**.
2. Нажми оранжевую кнопку **«Гарантийный возврат»**.
3. Отметь позиции, которые возвращаются.
4. Опиши причину (обязательно).
5. **«Создать гарантийный заказ»**.

Создастся новый заказ — копия выбранных позиций с актуальными ценами, помеченный как «Гарантийный», на сумму 0 ₽. Дальше веди его как обычный.

## 1.8. Сценарий: отменить заказ

В выпадающем списке статусов выбери **«Отменён»** — попросит указать причину (минимум 10 символов).

## 1.9. Сценарий: распечатать заказ

Кнопка **«Печать PDF»** на странице заказа — откроет окно печати браузера с красивым бланком (позиции, цены, расчёт).

## 1.10. Сценарий: дублировать заказ

Если клиент сделал такой же заказ как раньше:

1. Открой старый.
2. **«Дублировать заказ»** → подтверди.

Создастся копия в статусе «Лид» с теми же позициями и услугами по актуальным ценам.

## 1.11. Удобные инструменты

### Главная страница

Три блока виджетов:

- **На сегодня** — заборы и доставки на сегодня.
- **По статусам** — что в работе, что готово, новые лиды, висящие заказы (>7 дней без даты), без координат.
- **Проблемные заказы** *(красным)* — просрочка по фактической дате, нераспределённые в логистике, заказы со статусом «к забору» или «готов» без адреса. Если проблем нет — будет зелёная плашка «✓ Проблемных заказов нет».

Клик по виджету — переход в соответствующий список с уже применёнными фильтрами.

### Заказы

Сверху — фильтры (мульти-выбор с поиском по названию):
- Статус, тип оплаты, № заказа, телефон/имя клиента, диапазон дат.
- Поле даты можно переключать: «по дате создания», «по дате забора», «по дате доставки».
- **Сортировка** — клик по заголовку колонки. Shift+клик — добавить колонку как доп. сортировку. Ctrl/Cmd+клик — убрать.
- **Экспорт Excel** — выгрузка списка в `.xlsx`.

### Позиции

Поиск конкретного ковра. Фильтры: статус, тип позиции, исполнитель, № заказа, № позиции в заказе.

### Логистика

Календарь на неделю. Левая колонка **«Без даты»** — заказы без назначенного забора/доставки.

- **Перетаскивай** карточку мышкой на день — дата сохранится.
- **Перетащи в «Без даты»** — снимется дата (вернётся в нераспределённые).
- В блоке «Без даты» по умолчанию видно первые 5 карточек, остальные раскрываются кнопкой **«Показать ещё N…»** — чтобы длинный список не заслонял дни недели.
- Сверху — карта с метками (синие — забор, зелёные — доставка). Клик по метке открывает заказ.
- Сбоку — сводка по районам. Клик по району фильтрует и карточки, и точки на карте.
- На карточке заказа — чип **«👤 не назначен»** / «👤 Имя водителя». Клик → модалка выбора водителя. В неё попадают только сотрудники с ролью, привязанной к типу позиции «Доставка» (или «Приём»). Универсалы (без роли) в водители НЕ попадают — иначе оператор по ошибке мог назначить водителем мастера чистки.

### Производство

Три режима через переключатель сверху:
- **По заказам** — карточки активных заказов целиком.
- **По позициям** — отдельные позиции в работе.
- **По услугам** — отдельные услуги, можно прямо тут перетаскивать между статусами «Создана / В работе / Готова».

В режиме «По услугам» — фильтры с поиском: сотрудник, тип позиции, услуга, район, № заказа.

### Карта на странице заказа

Под адресами — мини-карта. Синяя метка — забор, зелёная — доставка. Если меток нет — значит адрес ввели руками без подсказок DaData (координаты не сохранились).

## 1.12. Связь с разработчиком

Справа внизу всегда висит кнопка **💬 Связь с разработчиком**. Открывает окно:

1. Выбери тему: «А можем сделать вот так?», «Хочу такую функцию», «Ошибка в логике / поведении», «Визуальная ошибка», «Непонятно что делать».
2. Опиши проблему.
3. *(Опционально)* Приложи скриншот: вставкой из буфера обмена (Ctrl+V) или загрузкой файла.
4. **Отправить**.

Разработчик увидит обращение со страницы, на которой ты был в момент отправки, со скриншотом и временем.

## 1.15. Личный кабинет работника

Отдельный экран для тех, кто реально руками делает услуги — мастера чистки, прачки, водители. **Открывается с телефона или с моноблока на производстве**, не предполагает компьютерной грамотности.

### Вход

1. На странице входа оператора — внизу ссылка **«Вход для работника →»**.
2. Открывается экран «Кто пришёл?» — большие плитки с именами сотрудников (плюс роль мелким шрифтом).
3. Нажимаешь свою плитку → появляется цифровая клавиатура → вводишь 4 цифры → внутри.
4. Если PIN не задан — система предложит придумать самостоятельно (ввести дважды). Дальше супервизор может сбросить через карточку сотрудника.

Сверху есть переключатель языка (русский / узбекский / таджикский) — на случай, если оператору так удобнее.

### Главный экран — «Мои услуги»

Список услуг, которые **назначены лично мне** и ещё не закрыты. У каждой:
- Название услуги и тип позиции (например, «Чистка — Ковёр»).
- Номер заказа и имя клиента.
- Размеры (если оператор уже ввёл).
- Большая кнопка **«Взять в работу»** или **«Завершить»** (зависит от текущего статуса).
- Кнопка **«Размеры»** — открывает форму, где можно править длину, ширину, площадь, вес, описание и дефекты. Фактика часто отличается от того, что внёс оператор по телефону.

При нажатии «Взять в работу» открывается окно «Сфотографируйте вещь перед началом работы» — телефон сразу зовёт камеру. Можно пропустить, но кнопка появляется всегда. То же при «Завершить» — «Сфотографируйте результат работы».

### Откат

Кнопка `↶` рядом с «Завершить» — откатить статус назад. Внизу под завершёнными услугами тоже есть откат — на случай если ошибочно закрыл.

### Маршрут (для водителей)

Если работнику назначены доставки или заборы на сегодня — сверху появится кнопка **🚗 Маршрут**. Внутри — список точек в порядке по времени: тип (забор/доставка), время, клиент, адрес, телефон-ссылка (тапнуть → позвонить), сумма к получению.

**Печать маршрутного листа** — кнопка 🖨 в шапке: открывается окно печати, на первой странице сводный маршрутный лист с подписями клиентов, далее — отдельная накладная на каждого клиента. К моноблоку или принтеру через USB — нажал, бумага вылетела.

## 1.13. Чего делать НЕ надо

- ❌ Лезть в **Справочники** или **Сотрудники** — это работа администратора. Если что-то не хватает — попроси через форму обратной связи.
- ❌ Принудительно переключать статусы «В работе / Частично готов / Готов» — они сами встают по статусам услуг.
- ❌ Лезть в **логи** (если они вообще видны).

# ЧАСТЬ 2. ИНСТРУКЦИЯ АДМИНИСТРАТОРУ

> Эта часть — для того, кто настраивает систему: справочники, цены, сотрудников и роли, читает обращения и аналитику. Установкой сервера занимается сисадмин (см. `SERVER.md`).

Все администраторские разделы видны только в **режиме супервизора**. Кнопка снизу sidebar'а: *«👑 Режим супервизора»*. При включении вокруг экрана появится тонкая оранжевая рамка — индикатор того, что ты сейчас можешь править справочники.

## 2.1. Что нужно сделать перед передачей оператору

Чек-лист первичной настройки:

- [ ] **Типы позиций** заведены (Ковёр, Палас, Шторы… а также «Доставка», «Приём» — см. 2.3).
- [ ] **Атрибуты SKU** проверены (с релиза V10 14 атрибутов заведены автоматически: тип вещи, материал, диапазоны веса/площади/периметра/длины/ширины/пог. метров — см. 2.4).
- [ ] **Группы SKU** заведены (Стирка, Чистка, Реставрация, Доставка, Приём — см. 2.5).
- [ ] **Каталог SKU** заполнен — конкретные учётные единицы с ценами, типами расчёта и атрибутами (см. 2.2).
- [ ] **Модификаторы цены** настроены (см. 2.6).
- [ ] **Районы** проверены (по умолчанию — 18 районов СПб; см. 2.7).
- [ ] **Сотрудники** добавлены, у каждого назначена роль (см. 2.8 и 2.9).
- [ ] *(Опционально)* DaData-токен прописан сисадмином в `.env` для подсказок адреса.

После этого оператор может работать самостоятельно.

### Пример минимального набора для прачечной

| Раздел | Что завести |
|---|---|
| Типы позиций | Шторы, Покрывало, Плед, Доставка, Приём |

| SKU «Доставка стандартная» | Группа: Доставка · Тип расчёта: FIXED · Цена: 500 ₽ · Авто-добавлять: ✓ · Бесплатно от: 3000 ₽ · Атрибут `item_type`: «Доставка» |
| SKU «Приём в офисе» | Группа: Приём · FIXED · 0 ₽ · Авто-добавлять: ✓ · Атрибут `item_type`: «Приём» |

| SKU «Стирка штор 5–10 кг» | Группа: Стирка · По весу · 220 ₽/кг · Атрибуты: `item_type` = Шторы, `weight_min` = 5, `weight_max` = 10 |
| SKU «Глажка штор» | Группа: Глажка · По площади · 80 ₽/м² · Атрибут `item_type`: Шторы |

После этого оператор может создавать заказ → выбрать клиента → добавить позицию «Шторы» с весом → в «+ Добавить услугу» увидеть подходящую «Стирка штор 5–10 кг» или «Стирка штор 2–5 кг» в зависимости от веса.

## 2.2. Справочники → Каталог SKU

**SKU** *(stock-keeping unit)* — учётная единица каталога. Каждая запись описывает конкретную услугу с конкретной ценой для конкретного диапазона параметров: например, *«Стирка ковёр шерсть 5–10 кг»*, *«Чистка ковра по площади»* или *«Доставка стандартная»*.

> **Зачем каталог именно такой.** Раньше услуги жили в виде двумерной таблицы «тип позиции × шаблон услуги» (например, ячейка «Ковёр × Чистка»). Это плохо масштабировалось — нельзя было задать «стирка от 5 до 10 кг — 250 ₽/кг, от 10 до 20 кг — 200 ₽/кг» без дублирования типов. С релиза V10 каталог плоский, а атрибуты задают, для каких позиций SKU подходит. Подбор подходящего SKU при оформлении заказа выполняет сама система (см. *«Только подходящие»* в инструкции оператора, §1.4 шаг 7).

**Поля SKU:**

- **Группа** — логическая категория («Стирка», «Чистка», «Доставка»…). Группы заводятся в отдельном разделе (см. 2.5) и используются как первый фильтр в окне выбора услуги.
- **Название** — что увидит оператор и клиент в PDF-акте.
- **Тип расчёта**:
  - **Фиксированная** — постоянная сумма.
  - **По весу** — цена × вес позиции (кг).
  - **По площади** — цена × площадь позиции (м²).
  - **По периметру** — цена × периметр (м). Периметр у позиции — отдельная цифра, не вычисляется автоматически из длины×ширины (овальные/круглые ковры).
  - **По длине** — цена × длина.
  - **По ширине** — цена × ширина.
  - **По пог. метру** — цена × погонные метры.
- **Цена** — основа расчёта (см. тип расчёта).
- **Себестоимость** — опционально, для аналитики маржи. Если не указана, в Доходности услуга показывается с пометкой «себестоимость не задана».
- **Авто-добавлять в каждый новый заказ** *(чекбокс)* — если включён, при создании любого заказа эта SKU добавится автоматически как отдельная позиция + услуга. Используется для доставки и приёмки.
- **Бесплатно от (₽)** — порог суммы заказа, выше которого цена этой услуги становится 0. Например, доставка с порогом 3 000 ₽ автоматически обнулится, когда оператор заполнит заказ выше этой суммы. Пересчёт идёт автоматически при каждом изменении состава.
- **Атрибуты** — гибкий набор пар «ключ → одно или несколько значений». Список ключей — это справочник атрибутов (см. 2.4). Самый важный ключ — **`item_type`**: к каким типам позиций применима эта SKU (например, Чистка ковра — `item_type = Ковёр, Палас, Покрывало`). Численные ключи (вес, площадь и т.п.) задают диапазон: SKU «Стирка ковёр 5–10 кг» получит `weight_min = 5` и `weight_max = 10`.

**Как работает подбор.** Когда оператор открывает окно «+ Добавить услугу» на позиции заказа:

1. Система берёт параметры позиции: `item_type_id`, вес, площадь, периметр, длина, ширина, погонные метры.
2. Для каждой SKU проверяет:
   - попадает ли тип позиции в значения атрибута `item_type` (если он задан в SKU),
   - попадает ли вес/площадь/… позиции в диапазон `*_min … *_max` (если эти атрибуты заданы).
3. Если все указанные атрибуты совпали — SKU помечается как **подходящая** (`matches=true`) и подсвечивается зелёной полоской.
4. Атрибуты, которые в SKU не заданы, игнорируются — то есть «Стирка ковра 5–10 кг» без указания материала подойдёт для всех ковров в этом диапазоне веса.

**История изменений.** Каждое сохранение SKU создаёт новую **версию** в `sku_versions` со снапшотом полей и атрибутов. У услуги в уже созданном заказе остаётся ссылка на конкретную версию — поэтому изменение цены здесь **не пересчитывает старые заказы** (это сделано намеренно). Историю видно по клику на 🕒 в строке SKU: версия, цена, себестоимость, кто и когда менял.

**Удаление SKU — мягкое.** Помеченная как удалённая SKU (`is_deleted = true`) исчезает из окна выбора услуг, но в старых заказах продолжает отображаться. Жёсткое удаление невозможно из-за привязки к заказам.

## 2.3. Справочники → Типы позиций

Тип позиции — вид изделия клиента (Ковёр, Палас, Шторы, Покрывало…). В V10 типы позиций — это **просто справочник имён**, без цены и без флага «по умолчанию». Логика «эта позиция добавляется в каждый заказ» теперь живёт в SKU (флаг «авто-добавлять» — см. 2.2).

Поля:
- **Название** — единственное поле.

Удаление мягкое: если тип уже использовался в позициях заказов, он скрывается из выпадающих списков, но в исторических данных остаётся.

> **Совет про «Доставка» и «Приём».** Эти типы лучше тоже завести в справочнике — тогда соответствующие SKU («Доставка стандартная», «Приём в офисе») смогут ссылаться на них в атрибуте `item_type`. На странице заказа авто-добавленные позиции «Доставка» / «Приём» будут отображаться как обычные строки.

## 2.4. Справочники → Атрибуты SKU

Справочник ключей атрибутов, которые можно задавать в SKU (см. 2.2). При старте Flyway-миграция (V10) заводит 14 базовых атрибутов:

| Ключ                  | Лейбл              | Тип значения           | Ед. изм. |
|-----------------------|--------------------|------------------------|----------|
| `item_type`           | Тип вещи           | Ссылка на тип позиции  | —        |
| `material`            | Материал           | Строка                 | —        |
| `weight_min`, `weight_max`     | Вес от / Вес до          | Число         | кг       |
| `area_min`, `area_max`         | Площадь от / Площадь до  | Число         | м²       |
| `perimeter_min`, `perimeter_max` | Периметр от / до       | Число         | м        |
| `length_min`, `length_max`     | Длина от / Длина до      | Число         | м        |
| `width_min`, `width_max`       | Ширина от / Ширина до    | Число         | м        |
| `running_meters_min`, `running_meters_max` | Пог. метры от / до | Число   | м        |

Можно добавить свои (например, `colour` / Цвет / STRING) — будут доступны в редакторе SKU как ещё одна группа значений.

**Удаление атрибута** удалит все его значения у всех SKU. Используйте с осторожностью; если атрибут уже задан хотя бы в одном SKU, лучше его не трогать.

## 2.5. Справочники → Группы SKU

Логические категории каталога: «Стирка», «Чистка», «Реставрация», «Доставка», «Приём». Используются как первый фильтр в окне выбора услуги у оператора. Сами по себе никакой расчётной логики не несут — это просто этикетки для навигации.

Поля: **Название**.

## 2.6. Справочники → Модификаторы цены

Процентные скидки или наценки на заказ или клиента целиком:
- *Скидка пенсионерам* `-10%`
- *Срочный заказ* `+25%`
- *Постоянный клиент* `-5%`

Положительные = наценка (красным), отрицательные = скидка (зелёным). Один модификатор может висеть и на заказе, и на клиенте.

**Удаление блокируется**, если модификатор уже применён к каким-либо заказам или клиентам — нужно сначала снять привязки.

## 2.7. Справочники → Районы

При первом запуске система автоматически загружает 18 районов Санкт-Петербурга. Если работаете не в СПб — добавьте свои, скройте лишние («неактивен»).

Скрытый район остаётся в существующих заказах, но не появляется в выпадающих списках при создании новых.

## 2.8. Сотрудники

Список людей, которые выполняют услуги (мастера, водители, операторы).

Поля:
- **Имя**.
- **Телефон / Контакт** — формат с маской `+7 (XXX) XXX-XX-XX`, валидация по числу цифр.
- **Роль** — опционально (см. 2.9). Без роли сотрудник считается «универсалом» и может выполнять услуги для любых типов позиций *(но не попадает в водители — см. ниже)*.
- **PIN** — 4–10 цифр, личный код для входа в мобильный кабинет работника. Если не задан, сотрудник придумает себе сам при первом входе.

**Удалить сотрудника нельзя**, можно только **деактивировать**. Деактивированный не появляется в выпадающих списках, но его исторические услуги сохраняются.

## 2.9. Сотрудники → Роли (боковая панель)

Роль — это набор типов позиций, с которыми сотрудник умеет работать. Позволяет настроить, чтобы при назначении исполнителей оператор видел только подходящих мастеров, а в водители не попадали мастера чистки.

**Создание роли:**
1. Справа на странице «Сотрудники» — панель «Роли». Нажми кнопку «развернуть» (`«`).
2. **+ Создать роль**.
3. **Название** (например, «Чистильщик ковров», «Водитель», «Прачка»), **описание** (опционально).
4. Выбери типы позиций (мульти-выбор с поиском) — те, с которыми эта роль умеет работать.

**Привязка роли к сотруднику:** в строке создания/редактирования сотрудника — выпадающий список «Роль» со всеми созданными ролями (или «без роли — универсал»).

**Фильтр по ролям:** клик по роли в боковой панели — таблица сотрудников отфильтруется. Клик ещё раз — фильтр снимется.

**Удаление роли блокируется**, если она привязана хотя бы к одному сотруднику. Сначала переведи их в другую роль (или сними роль), потом удаляй.

**Когда роль работает в заказе (назначение исполнителей):** в окно попадают сотрудники без роли (универсалы) + те, чья роль включает текущий тип позиции. В шапке окна написано, какие роли подходят, чтобы оператор понимал, почему список такой.

**Когда роль работает в логистике (назначение водителя):** в модалку выбора водителя попадают **только** сотрудники с ролью, привязанной к типу позиции, на который ссылается хотя бы один auto-add SKU (на практике — «Доставка» или «Приём»). **Универсалы (без роли) сюда не попадают** — это сделано специально, чтобы оператор не назначил по ошибке мастера чистки водителем.

**Минимальный комплект ролей для прачечной / производства:**
- *Оператор* — привязан к производственным типам (Ковёр / Шторы / Палас…), может закрывать услуги; в водители не попадает, если не привязан к «Доставке».
- *Водитель* — привязан к «Доставка» и «Приём». Попадает в логистике.
- *Рабочий* (Прачка / Чистильщик) — привязан к типам, по которым реально работает (Шторы для Прачки, Ковёр+Палас+Покрывало для Чистильщика).

## 2.10. Аналитика

Раздел **Аналитика** показывает:
- Заказы по районам — карта СПб с тепловой раскраской и таблица.
- Активные заказы по статусам — pie-chart.
- Типы позиций.
- Производительность сотрудников.
- Выручка по месяцам.
- Топ клиентов.
- Гарантия — у кого больше всего возвратов.
- Маржа по услугам.

Раздел **Доходность** (отдельный пункт меню в режиме супервизора):
- По типам позиций (с пометкой «себестоимость не задана» — услуги, у которых cost_price пустой).
- По клиентам.
- По сотрудникам — в т.ч. в разрезе услуг для конкретного сотрудника.
- По районам.
- По заказам — с фильтрами по периоду и клиенту.

## 2.11. Обращения

Раздел **Обращения** — это то, что присылают операторы через кнопку «Связь с разработчиком».

Каждая запись:
- Тема (можем сделать так, хочу функцию, ошибка логики, визуальная ошибка, непонятно).
- Текст.
- Скриншот (если был приложен).
- Страница, с которой отправлено.
- Автор и время.

**Статусы обращения:**
- *Новое* — только что создано.
- *Рассмотрено* — посмотрели.
- *Взято в работу* — начали делать.
- *Реализовано* — сделано.
- *Отказано* — не делаем.
- *Требуется пояснение* — попросили автора уточнить.

Меняй статусы через выпадающий список в карточке. Фильтры — по теме и по статусу.

## 2.12. Логи

В режиме супервизора:
- **Лог ошибок** — все 5xx-ошибки бэкенда с временем, путём и сообщением.
- **Лог действий** — все изменения данных (создание заказа, смена статуса, оплата и т.п.) — для аудита.

## 2.13. Что НЕ нужно делать

- ❌ Удалять типы позиций / SKU / атрибуты, если они уже использовались в заказах — система переведёт их в скрытый режим, но если вручную лезть в БД — ломается история.
- ❌ Раздавать всем операторам пароль «admin / foxy» — это дефолт для разработки. Сисадмин должен сменить его перед боевым запуском (см. `SERVER.md`).
- ❌ Менять цену SKU и ожидать, что старые заказы пересчитаются — этого не произойдёт намеренно (старая цена «приклеена» к версии SKU, на которую ссылается услуга). Новая цена начнёт работать в новых заказах.
- ❌ Менять структуру атрибутов «на ходу» (удалять `weight_min`, переименовывать `item_type`) во время записи демо — это сломает уже созданные SKU.

## 2.14. Подсказки адреса (DaData)

Если хочется автоподсказок адреса в форме заказа/клиента и автоматического определения района по координатам — попроси сисадмина прописать `VITE_DADATA_TOKEN` в `.env`. Бесплатный лимит DaData — 10 000 запросов в сутки, для одного оператора это безлимит.

Если ключа нет — поле адреса всё равно работает, просто без подсказок. Координат тоже не будет (на карте Логистики и заказа точек не появится). Район можно вводить руками из выпадающего списка.

# ЧАСТЬ 3. ТРЕНАЖЁР

Безопасный учебный стенд — копия приложения, которая работает на отдельной базе и порту. Любые действия (создание заказов, удаление клиентов, изменение цен) обратимы: одной кнопкой «Начать заново» демо-данные пересоздаются.

Используется для:

- **Обучения новых операторов.** При первом входе автоматически запускается интерактивный тур — подсветка всех разделов с подсказками. Оператор пробует «руками» создать заказ, поработать с логистикой, посмотреть аналитику.
- **Демонстрации потенциальным клиентам.** Можно тыкать всё что угодно — основная база не пострадает.
- **Проверки нового функционала** перед раскаткой в прод.

## 3.1. Что отличается от боевой системы

| | Боевая | Тренажёр |
|--|--|--|
| База | `carpet_db` | `carpet_training_db` |
| Порт backend | `8080` | `8081` |
| Порт frontend (dev) | `3000` | `3001` |
| Логин | свой | `admin` / `foxy` *(дефолт)* |
| Сверху экрана | — | зелёный баннер «Тренажёр» |
| Кнопка «Начать заново» | — | есть, в баннере |
| Интерактивный тур | — | запускается при первом входе |

## 3.2. Как запустить локально

**Один раз** — создать пустую БД для тренажёра:

```bash
createdb -U glebramazanov carpet_training_db
```

(если postgres-пользователь другой — подставьте его). Flyway сам накатит схему при первом старте.

**Backend в режиме тренажёра:**

```bash
cd backend
mvn spring-boot:run -Dspring-boot.run.profiles=training
```

Слушает `http://localhost:8081`. При старте видно в логах: `=== TRAINING MODE: пересоздаю демо-данные ===` — это сидер заливает клиентов, сотрудников, услуги и пример заказа.

**Frontend в режиме тренажёра:**

```bash
cd frontend
npm run dev:training
```

Слушает `http://localhost:3001`. Открываете в браузере → попадаете на логин (`admin` / `foxy`) → видите баннер «Тренажёр» сверху → автоматически стартует тур.

## 3.3. Управление туром

- **Автозапуск.** При первом входе тур стартует сам. После прохождения (Готово или Пропустить) — флаг сохраняется в `localStorage`, повторно не запустится.
- **Перезапуск.** В баннере сверху — кнопка «Начать тур». Сбрасывает флаг и запускает с первого шага.
- **Перевязка к UI.** Тур ищет элементы по `data-tour="..."`-атрибутам. Не привязан к классам/тексту — устойчив к рефакторингам. При добавлении новых разделов в навигацию просто проставьте им свой `data-tour`-id и допишите шаг в `frontend/src/training/TrainingTour.tsx`.

## 3.4. Сброс демо-данных

- **Из UI:** кнопка «Начать заново» в баннере → подтвердить → POST `/api/training/reset` → сидер пересоздаёт всю базу с нуля → страница перезагружается.
- **При перезапуске backend:** сидер всегда срабатывает на старте (CommandLineRunner). Если просто перезапустить `mvn spring-boot:run`, всё тоже сбросится.

## 3.5. Деплой тренажёра рядом с боевой

На том же сервере можно поднять две инстанции одновременно:

```text
boevoe.example.com   →  backend :8080  +  frontend (build/)
training.example.com →  backend :8081  +  frontend (build:training/)
```

NSSM-сервисы (см. `SERVER.md`):

- `CarpetBackend` — `mvn spring-boot:run` без профиля (или с `--spring.profiles.active=prod`)
- `CarpetTraining` — `java -jar ... --spring.profiles.active=training` с другим `SERVER_PORT=8081` и `SPRING_DATASOURCE_URL=...carpet_training_db`

Фронт собирается командой `npm run build:training` и кладётся в отдельную папку, на которую смотрит nginx или другой http-сервер.

## 3.6. Демо-данные

Сидер (`backend/src/main/java/ru/carpet/training/TrainingDataSeeder.java`) при каждом сбросе создаёт:

- 18 районов СПб
- 6 типов позиций (Ковёр, Палас, Шторы, Покрывало, Доставка, Приём)
- 5 групп SKU (Стирка, Чистка, Реставрация, Доставка, Приём)
- 5 SKU с EAV-атрибутами, включая 2 auto-add («Доставка стандартная» с порогом «бесплатно от 3000 ₽» и «Приём в офисе»)
- 14 базовых атрибутов из миграции V10 (item_type, material, weight_min/max, area_min/max, perimeter_min/max, length_min/max, width_min/max, running_meters_min/max)
- 3 роли (Мастер чистки, Прачка, Логист) + 4 сотрудника с привязкой к ролям
- 6 клиентов с **отдельным полем «Квартира»** (V18) — адрес чистый, квартира рядом бейджем
- ~18 заказов в разных статусах + 1 проблемный (V17) + 1 гарантийный (0 ₽)
- Логистическая волна на сегодня/завтра с **новыми слотами 17:00-18:00 / 18:00-19:00 / 19:00-20:00** (V18)

Если для демо нужно больше данных или другой набор — правьте сидер; никаких миграций не требуется.

> **Учётные данные тренажёра:** логин `admin`, пароль `foxy` (для оператора); PIN для входа в мобильный кабинет работника задаётся при первом входе.

### 3.6.1. Что показывает тренажёр (новые фичи)

Тур и демо-данные специально подсвечивают возможности последних спринтов — оператор-инструктор может пройти их «по сценарию»:

- **#1 Две позиции доставки**: при создании любого заказа автоматически появляются «Забор» и «Отвоз». Внутри каждой — платная Доставка, которую одним кликом «↔ Самовывоз» можно заменить на бесплатный самовывоз.
- **#2 Гарантийный заказ**: открыть заказ Иванова с пометкой «Гарантийный возврат» — все позиции и услуги 0 ₽ автоматически.
- **#3 Запятая в размерах**: поле длины/ширины принимает `0,4` (русская запятая) и `0.4` — оба работают, цена считается корректно (раньше Number('0,4')=NaN).
- **#4 1-часовой подынтервал**: при выборе времени доставки в дропдауне сначала идёт широкий слот «17:00-20:30», ниже отступом — 1-часовые подынтервалы 17:00-18:00, 18:00-19:00 …
- **#5 Импорт прошлой даты**: впишите Legacy ID в форме создания заказа — появится поле «Дата создания (из старой системы)».
- **#6 Слоты в справочнике**: будни 17:00-20:30, сб 10:00-20:30, вс — нет доставки. Хранятся в `delivery_time_slots`, редактируются через `/api/delivery-slots`.
- **#7 Квартира отдельно от адреса**: рядом с адресом — поле «Кв./офис», в адресе её больше нет (не мешает геокодированию). Тянется из карточки клиента.
- **#17 Проблемные заказы**: на заказе Кузьминой — поднятый «⚠ Проблема» и красный баннер с причиной. У админов в колокольчике — алерт. Снятие через «✓ Проблема решена».
- **#3 (уведомления) presence-tracking**: пока страница заказа открыта, новые уведомления именно этого заказа не появляются у этого пользователя.
- **#8 Аналитика — переключатель периода**: пресеты «Всё время / Текущий месяц / 7-30-90 дней» + ручной диапазон c/по. Все графики и таблицы перестраиваются.
- **#9 Клик по гарантийным**: в виджете «Гарантийная статистика» клик по красному числу → список гарантийных заказов клиента.
- **#12 Цвета по дню недели**: на карте в Логистике маркеры окрашены по дню (пн=красный, вт=оранжевый, …), полоска того же цвета — над колонкой дня.

Все эти фичи доступны и в боевой системе — тренажёр просто демонстрирует их на безопасной базе.
