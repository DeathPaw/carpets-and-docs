# Демо-сид под запись ролика прачечной

Три SQL-файла, применяются по очереди. Подробное описание сценария — `../DEMO.md`.

## Запуск

```bash
# Подставь свои user/db. Backend на это время должен быть остановлен.
DB_USER=glebramazanov
DB_NAME=carpet_db

psql -U $DB_USER -d $DB_NAME -v ON_ERROR_STOP=1 -f 00_cleanup.sql
psql -U $DB_USER -d $DB_NAME -v ON_ERROR_STOP=1 -f 01_core.sql
psql -U $DB_USER -d $DB_NAME -v ON_ERROR_STOP=1 -f 02_orders.sql
```

После этого запускаешь backend (`mvn spring-boot:run` в `../backend`) и frontend (`npm run dev` в `../frontend`). Логин `admin/foxy`.

## Что получится

- 12 типов позиций, 7 групп SKU, 12 SKU (включая 2 auto-add: Доставка с порогом 3000 ₽ и Приём)
- 5 ролей, 5 сотрудников с конкретными именами
- 3 модификатора цены, 7 клиентов (2 юрлица + 5 физлиц), у Astoria модификатор «Постоянный клиент −10%» уже привязан
- **22 заказа** в разных статусах: 2 от Astoria, 1 Park Inn, 5 физлиц, 7 «без даты», 7 архивных завершённых (для аналитики)

Подробная таблица заказов и какие сцены ролика что используют — см. `../DEMO.md` §0.

## Что НЕ покрывается сидом

Сразу после применения SQL **зайди вручную в UI**:

1. **Загрузить фото** на позиции скатерти и одного из пододеяльников в заказе Astoria #1 — реальные пятна, чтобы в сцене 3 показать. Без них блок «Фото» будет пустой.
2. **Задать PIN** для Светланы Петровой и Олега Соколова через карточку сотрудника в «Сотрудники» — без PIN-кода они не зайдут в мобильный кабинет. Дефолтный путь: первый вход → система предложит сам.

## Если что-то пошло не так

Просто прогони `00_cleanup.sql` + 01 + 02 ещё раз. Скрипт идемпотентен: чистит всё и заливает заново.
