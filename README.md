# Система учёта заказов — Производство ковров

Веб-приложение для учёта заказов на чистку, ремонт и обработку ковров: клиенты, заказы, позиции, услуги, исполнители, логистика, производство, оплата, гарантия.

Документ состоит из двух частей:

- **Часть 1 — Инструкция оператору.** Для человека, который ежедневно работает с приложением. Никаких технических знаний не нужно.
- **Часть 2 — Инструкция администратору.** Для того, кто настраивает справочники (типы изделий, услуги, цены, сотрудники, роли, районы), читает обращения и аналитику.

> Установка и развёртывание сервера, автообновление из git, бэкапы — отдельный документ `SERVER.md` для сисадмина.

# ЧАСТЬ 1. ИНСТРУКЦИЯ ОПЕРАТОРУ

> Эта часть — для того, кто будет каждый день вести заказы. Никакого айти не нужно. Все действия делаются мышкой в браузере.

## 1.1. Вход

1. Открой браузер (Chrome, Edge, Safari — любой современный).
2. Введи адрес сайта (его даст администратор).
3. На экране входа набери логин и пароль.
4. После входа сразу попадаешь на главную страницу.

Если случайно закрыл вкладку — ничего страшного, просто снова войди. Никакие данные не теряются.

## 1.2. Меню (слева)

Все разделы — в боковой панели слева:

| Раздел        | Зачем                                                                  |
|---------------|------------------------------------------------------------------------|
| **Главная**   | Виджеты с цифрами на сегодня и блок «Проблемные заказы».              |
| **Заказы**    | Вся работа с заказами — твой главный экран.                            |
| **Позиции**   | Поиск конкретного ковра по разным признакам.                           |
| **Логистика** | Календарь на неделю: что забираем и доставляем по дням.               |
| **Производство** | Доска с заказами, позициями или услугами в работе.                  |
| **Аналитика** | Графики и цифры по выручке, заказам, статусам.                        |
| **Клиенты**   | База клиентов и их история.                                           |
| **Связь с разработчиком** *(плавающая кнопка справа внизу)* | Если что-то непонятно или сломалось — отсюда отправляешь обращение разработчику. |

Если включён режим супервизора (это для администратора, обычно тебе не нужно), вокруг экрана появится тонкая оранжевая рамка — значит видны дополнительные пункты меню (Справочники, Сотрудники, Доходность, Обращения, логи).

## 1.3. Жизненный цикл заказа

Понимать его важно — вся работа сводится к переключению заказа между статусами.

```
Лид → Создан → К забору → В работе → Частично готов → Готов → Доставлен → Завершён
                                                            │
                                                            └─ может появиться Гарантийный возврат
```

Что значит каждый статус:

- **Лид** — клиент только позвонил, ничего ещё не подтвердили.
- **Создан** — заказ оформлен, ковры пока у клиента.
- **К забору** — назначены дата и время, машина едет.
- **В работе** — мастера начали работать. *Ставится автоматически.*
- **Частично готов** — часть позиций готова, часть в работе. *Ставится автоматически.*
- **Готов** — всё сделано, ждём оплату и доставку. *Ставится автоматически.*
- **Доставлен** — клиент получил ковры.
- **Завершён** — заказ полностью закрыт (после доставки и оплаты).
- **Отменён** — заказ отменили.
- **Гарантийный возврат** — отдельный новый заказ, если клиент пожаловался уже после доставки.

**Вручную ты переключаешь только:**
- Лид → Создан
- Создан → К забору
- Готов → Доставлен (или сразу «Принять оплату» — кнопка делает обе операции)
- Любой → Отменён (с обязательным указанием причины)

> Над статусом есть кнопка **«?»** — она открывает памятку прямо в приложении. Если забыл что-то — открой её.

## 1.4. Сценарий: новый заказ

### Шаг 1. Создать заказ

1. В меню → **Заказы** → справа сверху **+ Новый заказ**.

### Шаг 2. Указать клиента

**Если клиент уже есть** — «Выбрать существующего», начни печатать имя/телефон/название.
- Если у клиента уже сохранён адрес, появится диалог *«Использовать адрес клиента?»* — нажми «Да» если адрес тот же, либо «Нет» и введи другой.

**Если клиент новый** — «Создать нового»:
- Тип: *Физ. лицо* / *Юр. лицо*.
- Заполни нужные поля. Телефон вводится в формате `+7 (XXX) XXX-XX-XX` — система сама подставит маску и проверит длину.
- При вводе телефона система ищет клиентов с таким же номером и предлагает выбрать существующего, чтобы случайно не создать дубль.
- В поле **Адрес** — выпадающий список реальных адресов с автоопределением района и координат. Выбери клавишами или мышкой.
- ИНН (для юрлица, опционально) — система проверяет контрольную сумму.

### Шаг 3. Указать адреса забора и доставки

По умолчанию используется адрес клиента. Если нужны другие — поставь галку *«Указать другие адреса для заказа»* и заполни.

Если адрес уже подтверждён (взят из карточки клиента или выбран из подсказок DaData) — никаких предупреждений нет. Если ввёл руками без подсказок, появится бейдж *«адрес не подтверждён»* — координат не будет, на карте точка не отобразится.

### Шаг 4. Создать заказ → откроется страница заказа

На этом этапе у заказа статус **Лид**.

### Шаг 5. Добавить позиции (ковры)

Каждая позиция — это один ковёр или одно изделие.

1. На странице заказа — раздел **«Позиции заказа»** → **+ Добавить позицию**.
2. Выбери **тип** (Ковёр шерстяной, Палас и т.п.).
3. **Описание** — то, что отличает этот ковёр («зелёный 2×3 из спальни», «персидский»).
4. **Добавить**.

> **Совет.** Если у клиента несколько одинаковых изделий — после первого добавления нажми кнопку **Дубль** в строке этой позиции.

В заказ автоматически добавляются «дефолтные» позиции (доставка, оформление, приём) — их добавлять руками не надо. У них в строке висит маркер «дефолт». Их цены пересчитываются автоматически.

### Шаг 6. Заполнить размеры

Размеры нужны для услуг, цена которых считается по площади/весу/периметру. Без размеров такая услуга всё равно добавится, но её нельзя будет перевести в работу.

1. В строке позиции кликни на колонку **Размеры**.
2. Заполни нужные поля:
   - длина и ширина — для услуг «по площади»;
   - вес — для «по весу»;
   - длина+ширина или погонные метры — для «по периметру».
3. Зелёная галочка — сохранить.

### Шаг 7. Добавить услуги к позиции

1. Разверни позицию (▼).
2. В подразделе **«Услуги»** → выпадающий список **«+ Добавить услугу...»**.
3. Выбери. Цена посчитается сама из прайс-листа с учётом размеров.

> **Если у позиции не заполнены размеры**, при добавлении услуги откроется окно: можно сразу ввести нужные размеры или пропустить (тогда услуга добавится, но «заблокирована» — её нельзя будет перевести в работу).

> **Дубли запрещены.** Одну и ту же услугу нельзя добавить к одной позиции дважды. Если хочешь — можешь сначала отменить уже добавленную, тогда добавится новая.

> **Цена услуги для дефолтных типов** (доставка, оформление) не показывается — она уже учтена в стоимости самой позиции.

### Шаг 8. Дефекты, фото

- **Дефекты** — кликни на колонку «Описание / Дефекты» позиции, заполни второе поле. Защитит от споров с клиентом.
- **Фото** — разверни позицию, в блоке «Фото» нажми «Добавить фото». Несколько фото — клик по фото → открывается на полный экран.

### Шаг 9. Скидки/наценки

В блоке **«Расчёт стоимости»** внизу страницы заказа:
- **+ Добавить модификатор...** — выпадающий список (например, «Скидка пенсионерам -10%»).
- Если у клиента модификатор должен применяться всегда — после добавления нажми **«Сохранить модификаторы в клиента»**: в его новых заказах модификатор подставится автоматически.

### Шаг 10. Перевести в «Создан»

Сверху заказа — кнопка **«Сменить статус...»** → **Создан**.

### Шаг 11. Назначить дату забора

В блоке **«Логистика и детали»** → **«Редактировать»**:
- **Дата забора** + **Время забора** (есть три временных слота).
- **Сохранить**.

Затем сверху заказа смени статус на **К забору**.

> Дату удобно ставить через раздел **Логистика** — там можно перетаскивать заказы по дням мышкой.

## 1.5. Сценарий: ковры приехали в производство

1. Зайди в заказ (через «Заказы» или «Производство»).
2. Разверни позицию.
3. Найди услугу.
4. **Назначь исполнителя** — кнопка «Исполнители». Откроется окно со списком сотрудников.
   - В шапке окна написано, какая роль подходит для этого типа позиции (например, «Видны исполнители: с ролью "Чистильщик ковров" или без роли»). Это значит, что система автоматически отфильтровала тех, кто умеет работать с этим типом изделия.
   - Возле каждого имени — бейдж его роли или «универсал».
5. **Поставь статус услуги** через выпадающий список:
   - **Создана** — пока никто не делал.
   - **В работе** — мастер взял.
   - **Готова** — мастер закончил.
   - **Отменена** — отказались делать (нужна причина, минимум 10 символов).

Когда хотя бы одна услуга встала в **«В работе»**, статус заказа автоматически перейдёт в **«В работе»**. Когда часть позиций готова — **«Частично готов»**. Когда все — **«Готов»**.

## 1.6. Сценарий: заказ готов, клиент платит

Когда заказ перешёл в **«Готов»**:

**Вариант 1 (быстрый):** клиент пришёл и платит на месте.
- Появится зелёная кнопка **«Принять оплату»**.
- Окно: дата доставки, временной слот, тип оплаты.
- Жмём — заказ переходит в **«Доставлен»** + фиксируется оплата за один шаг.

**Вариант 2 (раздельный):**
1. Назначь дату доставки в блоке «Логистика и детали».
2. Смени статус на **«Доставлен»**.
3. Появится кнопка **«Оплатить»** — выбери тип оплаты.

После доставки и оплаты заказ можно перевести в **«Завершён»**.

## 1.7. Сценарий: гарантийный возврат

Клиент позвонил и пожаловался уже после доставки:

1. Открой заказ. Он должен быть в статусе **«Доставлен»** или **«Завершён»**.
2. Нажми оранжевую кнопку **«Гарантийный возврат»**.
3. Отметь позиции, которые возвращаются.
4. Опиши причину (обязательно).
5. **«Создать гарантийный заказ»**.

Создастся новый заказ — копия выбранных позиций с актуальными ценами, помеченный как «Гарантийный», на сумму 0 ₽. Дальше веди его как обычный.

## 1.8. Сценарий: отменить заказ

В выпадающем списке статусов выбери **«Отменён»** — попросит указать причину (минимум 10 символов).

## 1.9. Сценарий: распечатать заказ

Кнопка **«Печать PDF»** на странице заказа — откроет окно печати браузера с красивым бланком (позиции, цены, расчёт).

## 1.10. Сценарий: дублировать заказ

Если клиент сделал такой же заказ как раньше:

1. Открой старый.
2. **«Дублировать заказ»** → подтверди.

Создастся копия в статусе «Лид» с теми же позициями и услугами по актуальным ценам.

## 1.11. Удобные инструменты

### Главная страница

Три блока виджетов:

- **На сегодня** — заборы и доставки на сегодня.
- **По статусам** — что в работе, что готово, новые лиды, висящие заказы (>7 дней без даты), без координат.
- **Проблемные заказы** *(красным)* — просрочка по фактической дате, нераспределённые в логистике, заказы со статусом «к забору» или «готов» без адреса. Если проблем нет — будет зелёная плашка «✓ Проблемных заказов нет».

Клик по виджету — переход в соответствующий список с уже применёнными фильтрами.

### Заказы

Сверху — фильтры (мульти-выбор с поиском по названию):
- Статус, тип оплаты, № заказа, телефон/имя клиента, диапазон дат.
- Поле даты можно переключать: «по дате создания», «по дате забора», «по дате доставки».
- **Сортировка** — клик по заголовку колонки. Shift+клик — добавить колонку как доп. сортировку. Ctrl/Cmd+клик — убрать.
- **Экспорт Excel** — выгрузка списка в `.xlsx`.

### Позиции

Поиск конкретного ковра. Фильтры: статус, тип позиции, исполнитель, № заказа, № позиции в заказе.

### Логистика

Календарь на неделю. Левая колонка «Без даты» — заказы без назначенного забора/доставки.

- **Перетаскивай** карточку мышкой на день — дата сохранится.
- **Перетащи в «Без даты»** — снимется дата (вернётся в нераспределённые).
- Сверху — карта с метками (синие — забор, зелёные — доставка). Клик по метке открывает заказ.
- Сбоку — сводка по районам.

### Производство

Три режима через переключатель сверху:
- **По заказам** — карточки активных заказов целиком.
- **По позициям** — отдельные позиции в работе.
- **По услугам** — отдельные услуги, можно прямо тут перетаскивать между статусами «Создана / В работе / Готова».

В режиме «По услугам» — фильтры с поиском: сотрудник, тип позиции, услуга, район, № заказа.

### Карта на странице заказа

Под адресами — мини-карта. Синяя метка — забор, зелёная — доставка. Если меток нет — значит адрес ввели руками без подсказок DaData (координаты не сохранились).

## 1.12. Связь с разработчиком

Справа внизу всегда висит кнопка **💬 Связь с разработчиком**. Открывает окно:

1. Выбери тему: «А можем сделать вот так?», «Хочу такую функцию», «Ошибка в логике / поведении», «Визуальная ошибка», «Непонятно что делать».
2. Опиши проблему.
3. *(Опционально)* Приложи скриншот: вставкой из буфера обмена (Ctrl+V) или загрузкой файла.
4. **Отправить**.

Разработчик увидит обращение со страницы, на которой ты был в момент отправки, со скриншотом и временем.

## 1.13. Чего делать НЕ надо

- ❌ Лезть в **Справочники** или **Сотрудники** — это работа администратора. Если что-то не хватает — попроси через форму обратной связи.
- ❌ Принудительно переключать статусы «В работе / Частично готов / Готов» — они сами встают по статусам услуг.
- ❌ Лезть в **логи** (если они вообще видны).

## 1.14. Если что-то пошло не так

| Симптом                                          | Что сделать                                                       |
|--------------------------------------------------|-------------------------------------------------------------------|
| «Не заполнены размеры», услуга «Заблокирована»   | Заполни длину/ширину/вес позиции (зависит от услуги).             |
| Нельзя сменить статус — «переход не разрешён»    | Этот статус ставится автоматически. Закрой все услуги — догонит сам. |
| Не вижу нужной услуги в списке у позиции         | Услуга не привязана к этому типу позиции. Скажи администратору.    |
| Не вижу нужного типа изделия                     | Скажи администратору — добавит в справочник.                       |
| В списке исполнителей нет нужного сотрудника     | У сотрудника нет роли, которая включает этот тип позиции. Попроси администратора настроить роль. |
| Не появляются подсказки адреса                   | DaData не подключена — это разовая настройка администратора. Можно работать без подсказок, но координат не будет. |
| Адрес ввёл — на карте метка не появилась         | Метки появляются только если адрес был выбран из подсказок DaData. Введённое руками не имеет координат. |
| Заметил ошибку или хочется новую функцию          | Кнопка **«Связь с разработчиком»** справа внизу.                  |
| Сайт «лежит»                                     | Сообщи администратору — это вне твоей зоны.                      |

# ЧАСТЬ 2. ИНСТРУКЦИЯ АДМИНИСТРАТОРУ

> Эта часть — для того, кто настраивает систему: справочники, цены, сотрудников и роли, читает обращения и аналитику. Установкой сервера занимается сисадмин (см. `SERVER.md`).

Все администраторские разделы видны только в **режиме супервизора**. Кнопка снизу sidebar'а: *«👑 Режим супервизора»*. При включении вокруг экрана появится тонкая оранжевая рамка — индикатор того, что ты сейчас можешь править справочники.

## 2.1. Что нужно сделать перед передачей оператору

Чек-лист первичной настройки:

- [ ] **Шаблоны услуг** заведены (см. 2.2).
- [ ] **Типы позиций** заведены, включая «дефолтные» (доставка, оформление, приём — см. 2.3).
- [ ] **Прайс-лист** активирован для нужных пар «тип × услуга» (см. 2.4).
- [ ] **Модификаторы цены** настроены (см. 2.5).
- [ ] **Районы** проверены (по умолчанию — 18 районов СПб; см. 2.6).
- [ ] **Сотрудники** добавлены, у каждого назначена роль (см. 2.7 и 2.8).
- [ ] *(Опционально)* DaData-токен прописан сисадмином в `.env` для подсказок адреса.

После этого оператор может работать самостоятельно.

## 2.2. Справочники → Шаблоны услуг

Услуга — это то, что мы делаем с изделием (Сухая чистка, Стирка, Ремонт бахромы, Пропитка от пятен).

Поля:
- **Название** — видит оператор.
- **Тип расчёта цены**:
  - **Фиксированная** — постоянная сумма (например, антистатическая обработка — 500 ₽).
  - **По площади** — цена × длина × ширина. Требует длину и ширину у позиции.
  - **По весу** — цена × вес. Требует вес.
  - **По периметру** — цена × периметр. Требует длину+ширину или погонные метры.

Если тип «по площади/весу/периметру», а оператор пытается перевести услугу в работу без размеров — система покажет ему модальное окно с полями для ввода.

**Удаление услуги — мягкое.** Услуга с `is_deleted = true` исчезает из форм добавления, но в исторических заказах продолжает отображаться. Жёсткое удаление невозможно из-за привязки к заказам.

## 2.3. Справочники → Типы позиций

Тип позиции — вид изделия (Ковёр шерстяной, Ковролин, Палас, Дорожка).

Поля:
- **Название**.
- **По умолчанию** *(галочка)* — автоматически добавляется в каждый новый заказ как отдельная позиция. Используется для сопутствующих услуг типа доставки.
- **Цена** — стоимость по умолчанию (для дефолтных типов).
- **Бесплатно от** — порог суммы заказа, выше которого позиция становится бесплатной (например, доставка бесплатна при заказе от 4000 ₽). Цена пересчитывается автоматически при изменении состава заказа.

**Дефолтные типы и их услуги.** Если в прайс-листе для дефолтного типа активирована услуга — она автоматически попадает в каждый новый заказ вместе с самой позицией. Например, тип «Доставка» с активной услугой «Доставка» — в каждом заказе автоматически появится и позиция, и услуга, без ручного добавления оператором.

**Удаление типа — мягкое** (как и для услуг).

## 2.4. Справочники → Прайс-лист

Таблица «тип позиции × услуга». В каждой ячейке:
- **Цена** — для обычных типов. Если ячейка пустая → услуга недоступна для этого типа.
- **Себестоимость** — опционально, для аналитики маржинальности. Видна и редактируется всегда.
- **Чекбокс «доступна»** — для **дефолтных** типов. У них цена не используется (берётся из default_price), нужен только сам факт доступности услуги.

**Активная ячейка** подсвечена зелёным слева. Только активные пары появляются в выпадающем списке у позиции в заказе.

**Изменение цены здесь не пересчитывает уже созданные заказы** — это сделано намеренно: старые расчёты не должны меняться задним числом. Сохранение происходит при потере фокуса или нажатии Enter, без подтверждений.

## 2.5. Справочники → Модификаторы цены

Процентные скидки или наценки на заказ или клиента целиком:
- *Скидка пенсионерам* `-10%`
- *Срочный заказ* `+25%`
- *Постоянный клиент* `-5%`

Положительные = наценка (красным), отрицательные = скидка (зелёным). Один модификатор может висеть и на заказе, и на клиенте.

**Удаление блокируется**, если модификатор уже применён к каким-либо заказам или клиентам — нужно сначала снять привязки.

## 2.6. Справочники → Районы

При первом запуске система автоматически загружает 18 районов Санкт-Петербурга. Если работаете не в СПб — добавьте свои, скройте лишние («неактивен»).

Скрытый район остаётся в существующих заказах, но не появляется в выпадающих списках при создании новых.

## 2.7. Сотрудники

Список людей, которые выполняют услуги (мастера, водители).

Поля:
- **Имя**.
- **Телефон** — формат с маской `+7 (XXX) XXX-XX-XX`, валидация по числу цифр.
- **Роль** — опционально (см. 2.8). Без роли сотрудник считается «универсалом» и может выполнять услуги для любых типов позиций.

**Удалить сотрудника нельзя**, можно только **деактивировать**. Деактивированный не появляется в выпадающих списках, но его исторические услуги сохраняются.

## 2.8. Сотрудники → Роли (боковая панель)

Роль — это набор типов позиций, с которыми сотрудник умеет работать. Позволяет настроить, чтобы при назначении исполнителей оператор видел только подходящих мастеров.

**Создание роли:**
1. Справа на странице «Сотрудники» — панель «Роли». Нажми кнопку «развернуть» (`«`).
2. **+ Создать роль**.
3. **Название** (например, «Чистильщик ковров»), **описание** (опционально).
4. Выбери типы позиций (мульти-выбор с поиском) — те, с которыми эта роль умеет работать.

**Привязка роли к сотруднику:** в строке создания/редактирования сотрудника — выпадающий список «Роль» со всеми созданными ролями (или «без роли — универсал»).

**Фильтр по ролям:** клик по роли в боковой панели — таблица сотрудников отфильтруется. Клик ещё раз — фильтр снимется.

**Удаление роли блокируется**, если она привязана хотя бы к одному сотруднику. Сначала переведи их в другую роль (или сними роль), потом удаляй.

**Когда роль работает в заказе:** при назначении исполнителей в окно попадают только сотрудники без роли (универсалы) + те, чья роль включает текущий тип позиции. В шапке окна написано, какие роли подходят, чтобы оператор понимал, почему список такой.

## 2.9. Аналитика

Раздел **Аналитика** показывает:
- Заказы по районам — карта СПб с тепловой раскраской и таблица.
- Активные заказы по статусам — pie-chart.
- Типы позиций.
- Производительность сотрудников.
- Выручка по месяцам.
- Топ клиентов.
- Гарантия — у кого больше всего возвратов.
- Маржа по услугам.

Раздел **Доходность** (отдельный пункт меню в режиме супервизора):
- По типам позиций (с пометкой «себестоимость не задана» — услуги, у которых cost_price пустой).
- По клиентам.
- По сотрудникам — в т.ч. в разрезе услуг для конкретного сотрудника.
- По районам.
- По заказам — с фильтрами по периоду и клиенту.

## 2.10. Обращения

Раздел **Обращения** — это то, что присылают операторы через кнопку «Связь с разработчиком».

Каждая запись:
- Тема (можем сделать так, хочу функцию, ошибка логики, визуальная ошибка, непонятно).
- Текст.
- Скриншот (если был приложен).
- Страница, с которой отправлено.
- Автор и время.

**Статусы обращения:**
- *Новое* — только что создано.
- *Рассмотрено* — посмотрели.
- *Взято в работу* — начали делать.
- *Реализовано* — сделано.
- *Отказано* — не делаем.
- *Требуется пояснение* — попросили автора уточнить.

Меняй статусы через выпадающий список в карточке. Фильтры — по теме и по статусу.

## 2.11. Логи

В режиме супервизора:
- **Лог ошибок** — все 5xx-ошибки бэкенда с временем, путём и сообщением.
- **Лог действий** — все изменения данных (создание заказа, смена статуса, оплата и т.п.) — для аудита.

## 2.12. Что НЕ нужно делать

- ❌ Удалять типы или услуги, если они уже использовались в заказах — система переведёт их в скрытый режим, но если вручную лезть в БД — ломается история.
- ❌ Раздавать всем оператора пароль «admin / foxyisgood» — это дефолт для разработки. Сисадмин должен сменить его перед боевым запуском (см. `SERVER.md`).
- ❌ Изменять цены в прайс-листе и ожидать, что старые заказы пересчитаются — этого не произойдёт намеренно.

## 2.13. Подсказки адреса (DaData)

Если хочется автоподсказок адреса в форме заказа/клиента и автоматического определения района по координатам — попроси сисадмина прописать `VITE_DADATA_TOKEN` в `.env`. Бесплатный лимит DaData — 10 000 запросов в сутки, для одного оператора это безлимит.

Если ключа нет — поле адреса всё равно работает, просто без подсказок. Координат тоже не будет (на карте Логистики и заказа точек не появится). Район можно вводить руками из выпадающего списка.
