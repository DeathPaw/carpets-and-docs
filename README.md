# Система учёта заказов — Производство ковров

Веб-приложение для учёта заказов на чистку, ремонт и обработку ковров: клиенты, заказы, позиции, услуги, исполнители, логистика, производство, оплата, гарантия.

Документ состоит из двух частей:

- **Часть 1 — Настройка системы.** Для администратора (того, кто устанавливает и настраивает систему). Это разовая работа.
- **Часть 2 — Инструкция оператору.** Для человека, который ежедневно работает с приложением. Не требует никаких технических знаний.

---

# ЧАСТЬ 1. НАСТРОЙКА СИСТЕМЫ

> Эту часть выполняет администратор один раз при установке. Оператор сюда не заходит.

## 1.1. Что нужно установить на компьютер

| Компонент      | Версия    | Зачем                              |
|----------------|-----------|------------------------------------|
| Java           | 21+       | Запуск бэкенда                     |
| Maven          | 3.8+      | Сборка бэкенда                     |
| Node.js + npm  | 18+       | Сборка и запуск фронтенда          |
| PostgreSQL     | 14+       | База данных                        |

### macOS (Homebrew)
```bash
brew install openjdk@21 maven node postgresql@16
brew services start postgresql@16
```

### Ubuntu / Debian
```bash
sudo apt install openjdk-21-jdk maven nodejs npm postgresql postgresql-contrib
sudo systemctl start postgresql
```

## 1.2. База данных

Создать БД:
```bash
psql -U postgres -c "CREATE DATABASE carpet_db;"
```

Схема создаётся автоматически при первом запуске бэкенда — за это отвечает Flyway, миграции лежат в `backend/src/main/resources/db/migration/`. Ничего вручную выполнять не нужно.

## 1.3. Настройка бэкенда

Открыть `backend/src/main/resources/application.yml` и указать данные подключения к БД:

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/carpet_db
    username: <ваш PostgreSQL пользователь>
    password: <пароль или пусто>
```

Логин и пароль для входа в приложение задаются в `backend/src/main/java/ru/carpet/config/SecurityConfig.java`. По умолчанию: `admin` / `foxyisgood`. Поменять можно прямо в этом файле в методе `userDetailsService` — после изменения нужно пересобрать бэкенд.

## 1.4. Настройка фронтенда

По умолчанию фронтенд обращается к `http://localhost:8080`. Если бэкенд развёрнут по другому адресу, создать `frontend/.env`:
```
VITE_API_BASE_URL=http://your-backend-host:8080
```

## 1.5. Запуск

В двух терминалах:

```bash
# Терминал 1 — бэкенд
cd backend && mvn spring-boot:run     # http://localhost:8080
```

```bash
# Терминал 2 — фронтенд
cd frontend
npm install     # только при первом запуске
npm run dev     # http://localhost:3000
```

Открыть в браузере `http://localhost:3000`, войти под `admin / foxyisgood`.

## 1.6. Первичное заполнение справочников

Перед тем как передавать систему оператору, администратору нужно один раз заполнить справочники. Без этого оператор не сможет создать ни одной позиции в заказе.

Все справочники — на странице **Справочники** (в верхнем меню).

### 1.6.1. Шаблоны услуг

Что такое услуга: то, что мы делаем с ковром (например, *Сухая чистка*, *Стирка*, *Ремонт бахромы*, *Пропитка от пятен*).

Для каждой услуги нужно указать:
- **Название** — то, что увидит оператор.
- **Тип расчёта цены** — определяет, от чего зависит итоговая цена услуги:
  - **Фиксированная** — постоянная сумма (например, *Антистатическая обработка — 500 ₽*).
  - **По площади** — цена × длина × ширина. Требует у позиции заполненных длины и ширины.
  - **По весу** — цена × вес. Требует у позиции заполненного веса.
  - **По периметру** — цена × периметр (или цена × погонные метры). Требует длину+ширину или погонные метры.

Если выбран тип «по площади / по весу / по периметру», а у позиции не заполнены соответствующие размеры — услуга всё равно добавляется, но пометится «Заблокировано» и её нельзя будет перевести в работу, пока размеры не введут.

### 1.6.2. Типы позиций

Что такое тип позиции: вид изделия, с которым оператор будет работать (например, *Ковёр шерстяной*, *Ковёр синтетика*, *Ковролин*, *Дорожка*, *Палас*).

Кроме обычных типов есть **типы по умолчанию** (галочка «По умолчанию»). Они автоматически добавляются в каждый новый заказ как отдельная позиция и используются для сопутствующих услуг типа доставки. Для них указывается:
- **Цена** — стоимость по умолчанию (например, доставка = 400 ₽).
- **Бесплатно от** — порог суммы заказа, выше которого позиция становится бесплатной (например, доставка бесплатна при заказе от 4000 ₽).

Цены пересчитываются автоматически при каждом изменении состава заказа. Типичный сценарий: создать тип «Доставка» с галочкой «По умолчанию», ценой 400 ₽ и порогом 4000 ₽ — тогда доставка будет добавляться в каждый заказ автоматически и обнуляться, как только заказ перешагнёт 4000 ₽.

### 1.6.3. Прайс-лист

Прайс-лист — это таблица «тип позиции × услуга». В каждой ячейке либо стоит цена и услуга **активна** для этого типа (зелёная подсветка), либо ячейка пустая — услуга недоступна.

Что заполнять в каждой активной ячейке:
- **Цена** — сколько берём с клиента. Для типов *по площади/весу/периметру* это цена за единицу (₽ за м², ₽ за кг, ₽ за погонный метр).
- **Себестоимость** *(опционально)* — для аналитики и расчёта прибыли.

Услуга появится в выпадающем списке у позиции данного типа только если ячейка активна (там стоит цена).

### 1.6.4. Модификаторы цены

Модификатор — это процентная скидка или наценка, которую можно применять к заказу или к клиенту целиком. Примеры:
- *Скидка пенсионерам* — `-10%`
- *Срочный заказ* — `+25%`
- *Постоянный клиент* — `-5%`

Положительные значения = наценка (красный цвет в интерфейсе), отрицательные = скидка (зелёный). Один модификатор можно навешивать и на конкретный заказ, и на клиента (тогда он будет автоматически применяться ко всем его новым заказам).

### 1.6.5. Сотрудники

На странице **Сотрудники** завести всех людей, которые будут выполнять услуги (мастера по чистке, по ремонту, водители). На каждого: имя и контакт. Без активных сотрудников нельзя назначать исполнителей на услуги, и заказы не смогут перейти в статус «В работе».

## 1.7. Что должно быть готово перед передачей оператору

Чек-лист:

- [ ] Бэкенд и фронтенд запускаются и доступны.
- [ ] Оператор знает адрес сайта, логин и пароль.
- [ ] В справочнике **Шаблоны услуг** есть все услуги, которые предприятие реально оказывает.
- [ ] В справочнике **Типы позиций** заведены все виды ковров/изделий + хотя бы один «по умолчанию» (доставка).
- [ ] В **Прайс-листе** активированы и заполнены все нужные ячейки «тип × услуга».
- [ ] В справочнике **Модификаторы цены** заведены типовые скидки и наценки.
- [ ] На странице **Сотрудники** заведены все мастера и исполнители.

После этого оператор может работать самостоятельно — следующий блок написан для него.

# ЧАСТЬ 2. ИНСТРУКЦИЯ ОПЕРАТОРУ

> Эта часть — для того, кто будет каждый день вести заказы. Никакого айти не нужно. Все действия делаются мышкой в браузере.

## 2.1. Вход

1. Открой браузер (Chrome, Safari, Edge — любой современный).
2. Введи адрес сайта (его даст администратор).
3. На экране входа набери логин и пароль (тоже даст администратор).
4. После входа сразу попадаешь на главную страницу.

Если случайно закрыл вкладку — ничего страшного, просто снова войди. Никакие данные не теряются.

## 2.2. Что есть в меню

Сверху всегда виден список разделов. Заходи в них кликом:

| Раздел        | Зачем                                                                  |
|---------------|------------------------------------------------------------------------|

| **Логистика** | Календарь на неделю: что заберём и доставим в какие дни.              |
| **Производство** | Доска заказов, которые сейчас делают мастера.                       |
| **Аналитика** | Графики и цифры по выручке, заказам и т.п.                            |
| **Позиции**   | Поиск конкретного ковра по разным признакам.                          |
| **Сотрудники**| Список мастеров. Можно посмотреть, у кого сколько работы и заработка. |
| **Клиенты**   | База клиентов и история их заказов.                                   |
| **Справочники** | Цены, виды услуг, типы изделий. Сюда лучше не лезь — это работа администратора. |

Если что-то не открывается, не пугайся — просто нажми кнопку ещё раз или войди заново.

## 2.3. Главное правило: жизненный цикл заказа

Каждый заказ проходит по такой цепочке статусов. Понимать её важно, потому что вся работа — это переключение заказа из одного статуса в следующий.

```
Лид → Создан → К забору → В работе → Частично готов → Готов → Доставлен
                                                                    │
                                                                    └─ может появиться Гарантийный возврат (новый заказ)
```

Что значит каждый статус:

- **Лид** — клиент позвонил, ничего ещё не подтвердили. Можно собирать информацию.
- **Создан** — заказ оформлен, ковры пока у клиента, надо ехать забирать.
- **К забору** — назначена дата, машина едет к клиенту.
- **В работе** — ковры приехали в производство, мастера начали работать. **Этот статус ставится сам**, как только мастер берёт первую услугу в работу.
- **Частично готов** — часть ковров в заказе уже сделана, часть ещё в работе. **Сам ставится.**
- **Готов** — всё сделано, ждём оплату и доставку. **Сам ставится.**
- **Доставлен** — клиент получил ковры. Заказ закрыт.
- **Отменён** — заказ отменили на любом шаге.
- **Гарантийный возврат** — отдельный новый заказ, если клиент пожаловался уже после доставки.

**Важно:** статусы «В работе», «Частично готов» и «Готов» переключаются **автоматически** в зависимости от того, что мастера сделали с услугами. Тебе их вручную трогать не нужно.

Вручную ты переключаешь только:
- Лид → Создан
- Создан → К забору
- Готов → Доставлен
- Любой → Отменён

## 2.4. Сценарий: новый заказ от клиента

Это твой главный ежедневный сценарий. Делай по шагам.

### Шаг 1. Создать заказ

1. В меню нажми **Заказы**.
2. Справа сверху — кнопка **+ Новый заказ**.
3. Откроется форма.

### Шаг 2. Указать клиента

Тут два варианта:

**Если клиент уже есть в базе** — нажми «Выбрать существующего», начни вводить имя/телефон/название организации, выбери из выпадающего списка.

**Если клиент новый** — нажми «Создать нового». Дальше:
- Выбери тип: *Физ. лицо* или *Юр. лицо*.
  - Для физлица: фамилия, имя, телефон.
  - Для юрлица: название организации, контактное лицо, его телефон. ИНН — только если действительно нужен (галочка).
- Заполни адрес и район (если знаешь). Если адрес в Санкт-Петербурге — район определится автоматически примерно через секунду после ввода. Зелёная пометка «определён автоматически» означает что всё хорошо.
- Если клиент попросил указать что-то особенное (доп.телефон, комментарий) — заполни.

### Шаг 3. Указать адреса забора и доставки

Если адрес забора и доставки — это домашний адрес клиента, ничего не делай: система возьмёт адрес клиента сама.

Если это другой адрес (например, забрать у клиента, а доставить в офис) — поставь галочку **«Указать другие адреса для заказа»**:
- Введи адрес забора (район определится сам).
- Если адрес доставки тот же, оставь галочку «Адреса забора и доставки отличаются» **снятой**.
- Если адрес доставки другой — поставь эту галочку и введи второй адрес.

### Шаг 4. Создать заказ

Нажми **Создать**. Система откроет страницу нового заказа.

На этом этапе у заказа статус **Лид** — клиент позвонил, оформляем.

### Шаг 5. Добавить позиции (ковры)

Каждая позиция — это один ковёр (или одно изделие).

1. На странице заказа найди раздел **«Позиции заказа»**.
2. Нажми **+ Добавить позицию**.
3. Выбери **тип** (например, «Ковёр шерстяной»).
4. В поле **Описание** напиши то, что поможет потом отличить ковёр от других в заказе: «зелёный 2×3 из спальни», «персидский с орнаментом», и т.п.
5. Нажми **Добавить**.

Повтори для каждого ковра.

> **Совет.** Заметил, что у клиента много одинаковых дорожек? После того как добавил одну позицию и заполнил её, нажми кнопку **Дубль** в строке этой позиции — система создаст копию.

### Шаг 6. Заполнить размеры позиций

Зачем: цены большинства услуг считаются от размеров. Без размеров услуга не сможет уйти в работу.

1. В строке позиции кликни на колонку **Размеры** (там либо «—», либо уже значения).
2. Заполни нужные поля: длина, ширина, вес, площадь, погонные метры. Что именно нужно — зависит от услуг, которые ты планируешь применить:
   - Услуги «по площади» — нужны **длина и ширина**.
   - Услуги «по весу» — нужен **вес**.
   - Услуги «по периметру» — нужны либо **длина и ширина**, либо **погонные метры**.
3. Нажми зелёную галочку, чтобы сохранить.

### Шаг 7. Добавить услуги к каждой позиции

Услуги — это то, что мастера сделают с ковром: чистка, стирка, ремонт.

1. В строке позиции нажми **▼** слева, чтобы развернуть.
2. Появится подраздел **«Услуги»**. Справа — выпадающий список **«+ Добавить услугу...»**.
3. Выбери услугу. Система сразу посчитает её стоимость по прайс-листу с учётом размеров.
4. Если хочешь поправить цену вручную — кликни на цену услуги, введи новую, нажми галочку. Появится пометка «(ручная)».

> **Если у услуги вылез значок «Заблокировано»** — значит для этой услуги не хватает размеров. Вернись к шагу 6 и заполни нужные поля.

### Шаг 8. Записать дефекты (если есть)

Если на ковре есть пятна, пробелы, дефекты — кликни на колонку **Описание / Дефекты** позиции, во второе поле введи дефекты. Это пригодится мастеру и защитит от споров с клиентом.

### Шаг 9. Добавить фото позиции

1. Разверни позицию (▼).
2. В разделе **«Фото»** нажми **«Добавить фото»**, выбери файл.
3. Можно добавлять несколько фото. Клик по фото — открывает на полный экран.

Фото особенно важны, если на ковре есть дефекты или ценные особенности.

### Шаг 10. Применить скидки/наценки (если нужно)

В разделе **«Расчёт стоимости»** внизу страницы заказа:

- Чтобы добавить — выпадающий список **«+ Добавить модификатор...»**.
- Чтобы убрать — крестик рядом с модификатором.
- Если у клиента «Скидка пенсионерам» применяется всегда — сначала добавь её к заказу, потом нажми **«Сохранить модификаторы в клиента»**: в следующих заказах этого клиента она будет применяться автоматически.

### Шаг 11. Перевести заказ в статус «Создан»

Если заказ оформлен и клиент подтвердил:
1. Сверху заказа — выпадающий список **«Сменить статус...»**.
2. Выбери **«Создан»**.

Заказ ушёл из «Лидов» в активные.

### Шаг 12. Назначить дату забора

1. В блоке **«Логистика и детали»** нажми **«Редактировать»**.
2. Заполни **«Дата забора»** и выберите **«Время забора»** (есть три временных слота).
3. Нажми **«Сохранить»**.
4. Сверху смени статус заказа на **«К забору»**. Теперь машина знает, что ехать.

> Дату можно выставлять и через раздел **Логистика** — там удобно перетаскивать заказы по дням недели мышкой.

## 2.5. Сценарий: ковры приехали в производство

После того как мастер начал работать:

1. Зайди в нужный заказ (через **Заказы** или **Производство**).
2. Разверни позицию (▼).
3. Найди нужную услугу.
4. **Назначь исполнителя**: кнопка **«Исполнители»** → отметь галочкой нужных мастеров → **«Сохранить»**.
5. **Поставь статус услуги** через выпадающий список:
   - **Создана** — пока не делали.
   - **В работе** — мастер взял.
   - **Готова** — мастер закончил.
   - **Отменена** — отказались делать.

Когда хотя бы одна услуга встала в **«В работе»**, статус заказа автоматически перейдёт в **«В работе»**. Когда часть позиций готова — **«Частично готов»**. Когда все позиции готовы — **«Готов»**. Тебе ничего нажимать не надо.

## 2.6. Сценарий: заказ готов, клиент платит

Когда заказ перешёл в статус **«Готов»**:

1. Появится зелёная кнопка **«Оплатить»**.
2. Нажми её, выбери способ оплаты: **Карта**, **Наличные**, **Перевод**.
3. Нажми **«Оплатить»**. В заказе зафиксируется дата и тип оплаты.

Теперь нужно доставить ковры:

1. Назначь дату и время доставки в блоке **«Логистика и детали»** (как в шаге 12).
2. После того как водитель привёз ковры клиенту — смени статус на **«Доставлен»**.

Заказ закрыт.

## 2.7. Сценарий: гарантийный возврат

Если клиент позвонил и пожаловался уже после доставки:

1. Открой заказ. Он должен быть в статусе **«Доставлен»**.
2. Нажми оранжевую кнопку **«Гарантийный возврат»**.
3. В появившемся окне:
   - Отметь галочками те позиции, которые возвращаются.
   - В обязательном поле опиши причину (например, «остались пятна, клиент попросил переделать»).
4. Нажми **«Создать гарантийный заказ»**.

Создастся новый заказ — копия выбранных позиций, помеченный как «Гарантийный», на сумму 0 ₽. Дальше веди его как обычный заказ: «Лид» → «Создан» → «К забору» и т.д.

## 2.8. Сценарий: отменить заказ

В любой момент в выпадающем списке статусов выбери **«Отменён»**. Дальнейшая работа по нему не ведётся.

## 2.9. Сценарий: распечатать заказ для клиента

На странице заказа есть кнопка **«Печать PDF»** — формирует красивый бланк со всеми позициями, ценами, расчётом. Открывается окно печати браузера, можно распечатать на бумаге или сохранить в PDF.

## 2.10. Сценарий: дублировать целый заказ

Если клиент сделал такой же заказ, как раньше:

1. Открой старый заказ.
2. Нажми **«Дублировать заказ»**.
3. Подтверди.

Создастся копия в статусе «Лид» с теми же позициями и услугами, но с актуальными ценами из прайс-листа.

## 2.11. Удобные инструменты

### Главная страница (Дашборд)

Виджеты показывают на сегодня: сколько заборов, сколько доставок, сколько просрочек. Клик по виджету — переход в соответствующий список заказов.

### Логистика

Календарь на неделю с заказами по дням. Левая колонка «Без даты» — заказы, у которых дата забора/доставки не назначена. **Перетягивай мышкой** карточку на нужный день — дата сохранится автоматически. Удобно планировать неделю на 5 минут.

Внизу — сводка по районам: сколько заборов и доставок в каждом районе, на какую сумму. Клик по строке района — фильтр.

### Производство

Колонки «К забору / В работе / Частично готов» — все активные производственные заказы. Каждая карточка показывает: номер заказа, клиента, сколько услуг закрыто из общего числа. Удобно для контроля «что зависло».

### Сотрудники

Клик по сотруднику → видишь все его услуги (можно фильтровать по статусу и датам) и заработок за период.

### Клиенты

Список всех клиентов. Можно искать, заходить в карточку, видеть все его заказы и заметки.

### Поиск конкретного заказа

В разделе **Заказы** сверху — фильтры:
- по статусу,
- по номеру,
- по типу оплаты,
- по телефону клиента,
- по имени клиента,
- по диапазону дат.

И ещё **«Экспорт CSV»** — выгрузка в таблицу для Excel.

## 2.12. Чего делать НЕ надо

- ❌ Заходить в **Справочники** и менять цены/типы — это разрушит расчёты по уже идущим заказам. Если что-то не хватает — попроси администратора добавить.
- ❌ Удалять сотрудников, у которых уже есть назначенные услуги — лучше пометить «неактивный» (если такой переключатель есть).
- ❌ Принудительно переключать статус заказа в «Готов», не закрыв все услуги — заказ всё равно сам пересчитает по позициям.
- ❌ Лезть в **Лог ошибок / Лог** — это для администратора.

## 2.13. Что делать, если что-то пошло не так

| Симптом                                       | Что сделать                                                       |
|-----------------------------------------------|-------------------------------------------------------------------|
| Не могу сохранить услугу — пишет «не заполнены размеры» | Заполни длину, ширину или вес позиции (зависит от типа услуги). |
| Услуга «Заблокирована»                        | То же — у позиции не заполнены нужные размеры.                  |
| Не могу перевести статус — пишет «переход не разрешён» | Этот переход делается автоматически, не вручную. Закрой все услуги — статус заказа догонит сам. |
| Не вижу нужной услуги в списке у позиции      | Услуга не привязана к этому типу позиции. Скажи администратору, что нужно активировать ячейку в прайс-листе. |
| Не вижу нужного типа изделия                  | Скажи администратору — нужно добавить в справочник «Типы позиций». |
| Адрес не определяет район автоматически       | Введи район руками. Автоопределение работает только для Санкт-Петербурга. |
| Случайно нажал «Удалить» — что-то пропало     | Если удалилась позиция или услуга — придётся завести заново. Заказы целиком удалить нельзя — только отменить. |
| Сайт «лежит» / не открывается                 | Сообщи администратору — это вне твоей зоны ответственности.      |

## Структура проекта (для администратора)

```
.
├── backend/                              # Spring Boot 4.0.2 (Java 21, чистый JDBC)
│   ├── src/main/java/ru/carpet/
│   │   ├── controller/                   # REST-эндпоинты /api/*
│   │   ├── service/                      # Бизнес-логика, статусы, цены
│   │   ├── repository/                   # NamedParameterJdbcTemplate
│   │   ├── model/                        # Java records
│   │   ├── dto/                          # Request/Response с @Valid
│   │   ├── exception/                    # 404 / 409 / 422 + глобальный handler
│   │   └── config/                       # CORS, Security (basic auth), Flyway
│   └── src/main/resources/
│       ├── application.yml               # БД, порт, Flyway, Jackson snake_case
│       └── db/migration/                 # V1..V10 — Flyway-миграции
└── frontend/                             # React 18 + TypeScript + Vite
    └── src/
        ├── api/                          # HTTP-клиенты по доменам
        ├── pages/                        # Страницы (роуты)
        ├── components/                   # Layout, Toast, ConfirmModal, ErrorBoundary
        ├── types/                        # TypeScript-типы (snake_case как в API)
        └── index.css                     # Глобальные стили
```

## Стек

- **Бэкенд:** Java 21, Spring Boot 4.0.2, Spring Security (Basic Auth), Spring JDBC, Flyway, PostgreSQL.
- **Фронтенд:** React 18, TypeScript, Vite, React Router, Axios.
- **API-формат:** snake_case end-to-end (БД → Jackson → JSON → TS-типы).
- **Авторизация:** HTTP Basic, in-memory user в `SecurityConfig`.
